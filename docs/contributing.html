Contribution principles

Native first

Prefer browser APIs over packages for core effects.

Standalone

Every effect folder must remain independently understandable and runnable.

Bounded

Animation loops must have explicit limits and safe control ranges.

Documented

Every new effect ships with HTML, CSS, JavaScript, and a substantial README.

Development workflow

Create a branch

git checkout -b feat/my-effect

Implement and document

Keep the visual simulation separate from reusable runtime behavior.

Run verification

bun run verify

Open a focused pull request

Describe visual behavior, performance impact, accessibility considerations, and testing performed.

New effect contract

effects/16-example-effect/
├── README.md
├── index.html
├── style.css
└── script.js

The HTML must expose the shared studio IDs used by the verifier. The JavaScript must parse successfully, bind only to existing DOM IDs, and keep animation work bounded.

Pull request quality bar

  • No unexplained dependency additions.
  • No broken keyboard controls.
  • No console errors during normal use.
  • Responsive at narrow widths.
  • README explains configuration, reuse, performance, and troubleshooting.
  • Repository verifier passes.
